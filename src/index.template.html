顶部汇总卡的口径（重要）：顶部四张卡都是全账户口径 = 持仓表 + 已完成交易记录（已存档）：
  • 总收益 = 持仓浮动盈亏 ＋ 已实现盈亏（持仓内已平仓 ＋ 已存档的交易）
  • 已实现盈亏 = 持仓表里已平仓部分的净盈亏 ＋ 已存档交易的净盈亏（卡片副标题会写明各自多少）
  • 累计交易费用 = 持仓表买入/卖出费用 ＋ 已存档交易的费用
  • 总浮动盈亏只统计未了结的持仓——已存档的交易早已经了结，没有浮动盈亏
也就是说：把一笔交易存档后，它的已实现盈亏不会消失，仍然计入顶部「总收益」，只是从持仓表移到了下方记录面板。下方「已完成交易记录」面板里的统计是只针对已存档部分的口径（所以它和顶部卡片的数字本来就不应该相等，两者的差额就是持仓表当前的部分）。
盈亏提醒：勾选「启用」，再填提醒线即可——盯的是「总浮动盈亏」（持仓表口径，不含已存档）：
  • 「总浮盈达到 X 元」= 总浮动盈利 ≥ +X 时提醒（止盈提醒）；「总浮亏达到 X 元」= 总浮动亏损 ≤ −X 时提醒（止损提醒）
  • 两条线都是填正数幅度，0 或留空表示该方向不提醒；只填一边也行（只要止盈提醒，或只要止损提醒）
  • 什么时候检查：每次点「⟳ 刷新现价」取到新价之后；打开页面时（若没开自动刷新）；手工改完表格里的「当前价 / 单价 / 股数」之后。开了自动刷新就跟着定时检查
  • 不会反复弹：越过提醒线只弹一次，之后即使还在线上也不再弹；要等浮动盈亏回到线内（留 1% 回差，避免在线上抖动）后重新越线才会再提醒
  • 右侧状态文字实时显示「当前总浮动 / 提醒线 / 是否已越过」，另有「测试提醒」按钮可以先看看弹窗长什么样（不会改变提醒状态）
  • 若还有持仓没填当前价，弹窗里会说明「浮动盈亏不完整」，避免把不完整的数字当成全部
怎么做空（融券卖出）：点「＋ 添加空头（卖空）」，或把已有行的方向标记从「多」切成「空」。做空时两张明细表角色对调： 空卖出明细 = 开仓（先融券卖出拿到钱），空买入明细 = 平仓（后买回还券）。 开仓在前、平仓在后，所以展开后卖出明细会排在左边。
成本口径采用加权平均法，多头与空头互为镜像：
  • 多含费成本价 = （Σ 买入金额 + Σ 买入费用）÷ Σ 买入股数
  • 多已实现盈亏 = （Σ 卖出金额 − Σ 卖出费用）− 平仓股数 × 含费成本价
  • 多浮动盈亏 = 剩余股数 × 当前价 − 预估卖出费用 − 剩余股数 × 含费成本价
  • 空含费开仓均价 = （Σ 卖出金额 − Σ 卖出费用）÷ Σ 卖出股数　（做空是"先收钱"，开仓价要减掉费用）
  • 空已实现盈亏 = 平仓股数 × 含费开仓均价 − （Σ 买入金额 + Σ 买入费用）
  • 空浮动盈亏 = 剩余空头 × 含费开仓均价 − （剩余空头 × 当前价 + 预估回买费用）　（股价跌 → 空头赚，方向是反的）
  • 两边都满足「总盈亏 = 已实现 + 浮动」，两个口径互斥，不重不漏
分层计价：每笔成交单独计提费用，最低佣金逐笔生效（500 股与 800 股各扣一次下限，而不是合并后扣一次）。
异常检测：多头卖出多于买入、或空头平仓（买回）多于开仓（卖出），剩余股数会标成橙色并给出提示，且禁止存档。
存档：点行尾「✓」会弹出存档窗口，里面是 清盘明细——这是必填的关键一步。自动刷新开着时「当前价」是市场实时价，未必等于你的真实成交价，所以存档时要单独录入你实际成交的价格；而且可以分多笔、不同价格不同数量（比如 300 股按 ¥12.10、500 股按 ¥12.35、200 股按 ¥11.90 分批清掉）。
  • 每笔清盘都是一笔独立成交，各自计提佣金/印花税，所以最低佣金也是逐笔生效的
  • 录入过程中下方会实时显示「还差 N 股 / 超出 N 股」，只有把待清盘股数恰好分配完「确认存档」才可点——不会多算也不会漏算
  • 「按剩余数量填一笔」可以一键把剩余股数补到当前行，适合最后一笔；「＋ 再添一笔」继续分批
  • 已逐笔录入过卖出（空头则是买回）明细的部分，仍按你录入的实际价格算；只有待清盘的那部分才用清盘明细补齐
  • 清盘价故意不预填实时价，避免顺手把市场价当成成交价存进历史
  • 如果这支股票已经全部卖出 / 买回，窗口会显示「待清盘：无」，不需要录入，确认即可
  • 窗口里还能改成交日期，事后补录旧交易时用得上（默认今天）
  • 存档回执会写明清盘情况：单笔显示成交价，多笔显示「N 笔均价」
强制清盘（数量对不上时用）：做 T、或者同一支股票多次进出之后，系统算出来的持仓数量可能和券商实际对不上 （最典型的：卖了 100 手，跌下来之后用同样的钱买回了 101 手——系统会显示"剩余 1 手"，而你的账户里是 101 手）。 这时用存档窗口里的 「强制清盘」模式，直接输入你实际的成交价和数量：
  • 数量可以比记录的多、也可以比记录的少，不做任何配平校验（这正是它的用途），窗口里会写明差了多少股
  • 盈亏按「价差 × 数量」结算（价差取大小，正负由方向决定），分两段： 已了结的那部分用记录里的真实成交均价算，其余用本次清盘价算； 两段数量之和 = 建仓数量。 多（已卖出均价 − 建仓买入均价）× 已卖出数量 ＋（清盘卖出均价 − 建仓买入均价）× 未了结数量； 空（开仓卖出均价 − 已买回均价）× 已买回数量 ＋（开仓卖出均价 − 清盘买回均价）× 未了结数量。 不扣交易费用，费用仍按当时费率逐笔计提、单独统计在顶部「累计交易费用」卡里。 ——分两段是为了不吞掉已了结部分的真实盈亏（它的成交价往往和清盘价不同）， 窗口里会把两段分开列出，同时给出金额差作对照
  • 确认后整支移入「已完成交易记录」，记录里会带一个「强制清盘」标记，导出的 CSV 里也有对应备注， 便于和逐笔清盘的记录区分（两者口径不同，不该混着看）
  • 原来那些中间买卖记录不再单独计盈亏（都被这次结算覆盖），所以强制清盘后总收益的构成会重算一次
  • 持仓数量对不上（出现 ⚠ 卖出多于买入）的时候点「✓」，会直接以强制清盘模式打开， 不再被拦住——这种情况逐笔清盘永远配不平
  • 清盘价同样不预填实时价，数量也不预填（对不上的时候预填会把人锚定在错误的数字上）
存档的其他说明：多头必须全部卖出、空头必须全部买回才能整支存档（未了结的部分留在上表才能继续跟踪浮动盈亏；卖出多于买入会被判定为超卖，此时请用上面的「强制清盘」）。只想补录历史交易的话，加一支股票、填一笔开仓 + 一笔平仓（当前价留空）就行。存档时按当时的费率把金额锁死，之后再改费率不会篡改历史记录。
收益率分母：多头按「Σ 买入金额 + 买入费用」，空头按「Σ 卖出金额」（开仓名义金额）——融券的真实保证金比例因人而异、无法得知，所以不按保证金算。
实时行情（自动跟踪现价）：在「代码」栏填上代码，点「⟳ 刷新现价」，程序会直接把最新价写入「当前价」栏并重算全部盈亏；勾选「自动刷新」可按 10 秒 ~ 5 分钟定时取价（页面切到后台时会自动暂停，切回来立即补一次）。代码填写方式：
  • A股：直接填 6 位数字，如 600519、000001、300750、688981（自动判断沪深北）
  • ETF / 基金：同样 6 位，如 510300、159915
  • 港股：hk00700 或直接填 700；美股：usAAPL
  • 北交所：直接填 6 位即可（920002、430047、833171），也可写 bj430047。 实时价、涨跌幅、盈亏都能正常算；但历史 K 线（15 日分位）目前只有 920 开头的新代码段有可靠数据源， 43/83/87/88 开头的存量代码在看板里会显示「北交所老代码段暂无历史K线源」——宁可标不支持，也不用错数据算分位
  • 「名称」栏留空时，刷新后会自动把股票简称填进去
右侧「国际大宗商品」：固定显示三个品种——WTI 原油（NYMEX，接口里的名字是"纽约原油"）、布伦特原油（ICE，即布油）、伦敦金现（XAU/USD，现货黄金）。它们与持仓共用同一次刷新：点「⟳ 刷新现价」会一起更新；也可以点该面板右上角的 ⟳ 只刷这三个品种。鼠标悬停在某一行上能看到昨收、今开、最高、最低与行情时间。窗口不够宽时它会自动变成页面顶部的一条横排，不会挤占表格宽度。
取数方式（刷新失败时看这段）：正常走 fetch；若它被跨域策略或页面环境限制拦住，程序会自动改用 <script> 标签再取一次——这个接口返回的本来就是 JS 赋值语句（v_sh600519="…"），而脚本加载不受 CORS 限制，所以在 file:// 直接打开、或嵌在受限页面里也能取到；此时状态栏会写「已改用备用取数方式」。两条通道都失败才说明请求根本没发出去，那时请检查网络 / 代理 / 安全软件（它们可能拦了 qt.gtimg.cn）。
高低位看板（辅助周频高低切换）：持仓表里填了代码的股票会自动出现在「高低位看板」里；候选股用面板右上角的输入框加入观察池（观察池不参与任何盈亏统计，只是盯行情）。平仓存档后不会从看板消失：那支股票会带着「已平仓」标记继续留在看板上（连同你打的板块标签一起转过去），方便盯着它回落再买回；不想再盯了，点该行的「✕」即可从看板移除（不影响已完成记录与盈亏统计）。每行显示：
  • 15日分位：现价在近 15 个交易日高低区间里的位置，100 = 顶着区间最高（高位，偏卖），0 = 贴着最低（低位，偏买）；突破区间会标注「创 15 日新高 / 新低」
  • 15日最高 / 最低：区间两个边界价，下面的小字是现价距它们的百分比
  • 均线位置：现价相对 MA5 / MA10 / MA30 在上方还是下方（悬停看具体百分比）

数据保存在哪、怎么防丢：所有数据自动存在你本机浏览器的 localStorage 里，关网页、关电脑都还在，不需要每次保存。但它有三个软肋：换浏览器、清理浏览器数据、换电脑都会丢。所以请用「已完成交易记录」面板里的 ⤓ 导出备份 JSON 定期存一份——它包含持仓批次、已完成记录、费率、设置的全部内容，随时能用 ⤒ 导入 JSON 完整还原：
  • 导入方式可选：仅合并已完成记录（只追加备份里没有的记录，重复的自动跳过，持仓与费率不动）或 覆盖全部数据（用备份替换当前所有内容，会有二次确认）
  • 可以先点「解析内容」，看清楚这份备份含多少持仓、多少记录、累计收益多少、有多少笔与现有记录重复，再决定要不要导入
  • 「导出记录 CSV」和「导出 CSV」只用于导出查看（Excel 等），不能导回来——要能还原请用 JSON
  • 建议在每次大额清仓存档后导出一份，备份状态会显示在按钮右侧
