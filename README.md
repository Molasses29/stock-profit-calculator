# 股票收益计算器

**一个自包含的单文件网页工具：管持仓、盯高低位、守纪律、做复盘。**
双击 `index.html` 就能用，不需要服务器、不需要安装、不需要注册；所有数据只存在你自己的浏览器里，不上传任何地方。

> 记账按**加权平均法**（不是 FIFO），费用**逐笔计提**（买入佣金 / 卖出佣金 / 印花税 / 过户费，最低佣金逐笔生效）；支持分批建仓、分批卖出与**融券做空**。

---

## 为什么做这个

做短线真正的难点不是算盈亏，而是这三件事：

| 痛点 | 这个工具的做法 |
| --- | --- |
| 账算不清：分批建仓、做 T、各种费用，最后对不上券商 | 逐笔录入 + 加权平均结转，顶部汇总与持仓表、已完成记录三者互相可推导 |
| 不知道该卖谁、买谁 | 高低位看板：15 日分位 + 板块分组（组内按分位降序，**上面是该卖的、下面是该买的**） |
| 事前没计划、事后没法复盘 | 每支头寸记下理由/止损/目标/策略标签，自动算**仓位建议**与 **R 倍数**，按月汇总收益 |

## 功能

### 一、记账

- **分批买卖**：每支股票可逐笔录入多笔价格与股数，自动加权平均
- **做空（融券）**：空头时买入/卖出的角色对调，盈亏按「卖出净得 − 买回付出」逐笔结转
- **整支存档**：了结后移入「已完成交易记录」，含两种清盘方式
  - *逐笔清盘*：录入实际成交价，数量需恰好分配完
  - *强制清盘*：做 T、或数量与券商对不上时的逃生口，直接填实际成交价与数量，**不做配平校验**
- **导出**：持仓 CSV、已完成记录 CSV、完整备份 JSON（可再导入）
- 顶部汇总卡 = **全账户口径**（持仓表 ＋ 已存档），存档不会让数字凭空变小

### 二、盯盘

- **实时行情**：填代码一键取价（腾讯财经公开接口），支持 A 股 / 北交所 / 港股 / 美股 / ETF；可设 10 秒 ~ 5 分钟自动刷新
- **高低位看板**：每支股票显示现价在近 **15 个交易日**高低区间里的位置（分位）、距高低点百分比、与 MA5/MA10/MA30 的关系；候选股放进**观察池**（只看不记账）
- **板块标签 + 分组**：给持仓/观察股打板块标签（如「PCB」「光模块」），组内按分位从高到低排列
- **持仓行分位槽**：成本价是槽上固定的刻度，现价是浮动圆点（≥75 红 / ≤25 绿），一眼看出「买在什么位置、现在跑到哪」
- **三类提醒**（都带闩锁与回差，不会刷屏）：总浮动盈亏提醒、**分位越线提醒**、**止损/目标到线提醒**
- **国际大宗商品侧栏**：WTI 原油、布伦特原油、伦敦金现，与持仓共用一条刷新链路

### 三、纪律

- **交易计划**：每支头寸记下入场理由、策略标签、止损价、目标价
- **仓位反算**：填「账户资金 × 单笔风险%」→ 按 `资金 × 风险% ÷ 每股风险` 算出**建议股数**（100 股整手）
- **R 倍数**：`盈亏 ÷ 初始风险`（入场价到止损的距离）—— 短线唯一可跨仓位比较的成绩单位
- 平仓后不会从看板消失：存档的股票以「**已平仓**」标签留在看板上，方便盯它回落再买回（不想盯了点 ✕ 移除）

### 四、复盘

- **月度收益**：按成交月份汇总笔数、盈亏笔数、费用、当月净收益与累计（中间的收益柱：右伸红=盈利、左伸绿=亏损）
- 存档时自动快照当时的策略标签与止损/目标，为后续按策略归因统计留数据

## 数据与隐私

- 所有数据存在**浏览器本地的 localStorage**（键名 `stock-pl-calculator-v4`），不经过任何服务器，代码里**不含任何个人数据**
- ⚠️ **不要把导出的备份 JSON 提交到仓库**（那里面是你的真实持仓），`.gitignore` 已做拦截
- 换电脑 / 换浏览器：用「导出备份 JSON」→「导入」迁移
- 同一台电脑上，`file://` 打开的不同路径 / 不同文件名**共享**同一份 localStorage，重命名或移动文件不会丢数据；但换成 `http(s)` 访问（如 GitHub Pages）属于**另一个来源**，两者数据不共享
- 建议偶尔导出一次备份：localStorage 会被「清理浏览数据」清掉，且只存在这一台电脑上

## 计算口径（重要）

### 成本结转

- **加权平均法**（不是 FIFO）
- 费用逐笔计提：买入佣金 / 卖出佣金 / 印花税（仅卖出）/ 过户费，最低佣金逐笔生效
- 多空互为镜像：多头「买入 = 建仓、卖出 = 平仓」，空头「卖出 = 开仓、买入 = 平仓」
- 收益率分母：多头按「Σ 买入金额 + 买入费用」，空头按「Σ 卖出金额」（不按保证金）

### 顶部汇总卡 = 全账户口径

= **持仓表 ＋ 已存档**。总收益 = 浮动 + 已实现（持仓内 ＋ 已存档）。存档会把股票从持仓表移进已完成记录，所以任何汇总都必须把两处相加，否则数字会在存档瞬间凭空变小。

下方「已完成交易记录」面板的统计**只针对已存档部分**，与顶部口径本就不同，面板提示行会把两者写成可互相推导的形式。

### 强制清盘的盈亏口径

盈亏 = **价差 × 数量**，且**分两段**（价差取大小，正负由方向决定）：

| 段 | 数量 | 价格 |
|---|---|---|
| 已了结部分 | 记录里已经平掉的数量 | 记录里的**真实成交均价** |
| 清盘部分 | 建仓数量 − 已了结数量 | 本次输入的**清盘价** |

两段数量之和恒等于建仓数量，所以无「已了结部分」时会退化成「价差 × 建仓数量」。**不扣交易费用**（费用逐笔计提，单列在「累计交易费用」卡里）；窗口里会同时给出「金额差」作对照。

- 为什么分两段：强平前你可能已经先平掉一部分，那部分的成交价往往和清盘价不同；不分段等于用清盘价覆盖真实成交价，会把已了结部分的盈亏算错
- 为什么不用金额差：做 T「用同样的钱买回更多股」时买卖总金额几乎相等，金额差只剩手续费、看着像没赚，而真实赚到的是价差乘数量
- 数量不做配平校验（可多可少），清盘数量与记录剩余不一致时，**盈亏基数取记录剩余**，差异只影响记录里的股数

## 行情接口

腾讯财经公开接口（免费、无需 key、CORS 放行）：

- A股 / 港股 / 美股 / 北交所 / ETF：`qt.gtimg.cn`，`~` 分隔
- 国际原油 / 贵金属：`hf_CL`(WTI)、`hf_OIL`(布伦特)、`hf_XAU`(伦敦金现) 等，**逗号分隔**（与股票格式不同）
- 历史日 K：新浪财经（无 CORS 头，走 script 标签通道）

行情仅作参考，可能有延迟或误差，请以券商行情为准。

## 目录结构

```
stock-profit-calculator/
├─ src/
│  ├─ index.template.html   页面结构（含 {{STYLES}} / {{APP_JS}} / {{BUILD_STAMP}} 占位符）
│  ├─ styles.css            页面样式
│  └─ app.js                计算与交互逻辑
├─ scripts/
│  └─ build.mjs             构建工具：把 src/ 三份源码内联成自包含的 index.html
├─ test/
│  └─ app.test.mjs          jsdom 端到端测试（对**构建产物**跑完整交互链路，235 项断言）
├─ index.html               最终发布文件（由构建生成，需提交，GitHub Pages 直接用）
├─ package.json
├─ .gitignore
└─ README.md
```

**为什么源码拆开、产物仍然是一个文件？** 拆开是为了可维护（样式 30KB、逻辑 140KB 混在一个文件里很难改），产物合并是为了保住这个工具最大的优点：一个文件、双击就能用、离线可用、方便拷给朋友。

## 开发

```bash
npm install
npm run build     # 由 src/ 生成 index.html
npm run check     # 只检查 index.html 是否与 src/ 同步（CI / 提交前用，不同步则退出码 1）
npm test          # jsdom 端到端测试（对产物跑完整交互链路）
npm run verify    # check + test
```

### 测试版通道（新功能先隔离试用）

```bash
node scripts/build.mjs --beta          # 生成 ../股票收益计算器-测试版.html（不动 index.html）
node test/app.test.mjs --beta          # 对测试版产物跑同一套断言
```

测试版与正式版在构建期做了三处隔离，避免试用新功能时碰到正在使用的正式数据：

| 隔离项 | 正式版 | 测试版 |
| --- | --- | --- |
| 存储键 | `stock-pl-calculator-v4` | `stock-pl-beta-v1`（互不读写） |
| 旧版本键迁移 | 启用 | 关闭 |
| 标题 / 条幅 / 导出文件名 | 无标记 | 带「测试版」字样 |

改写都走 `subOnce()` —— 锚点必须恰好命中 1 处，源码改动后锚点对不上会**直接构建失败**，不会静默产出一个「看起来正常、其实没隔离」的版本。试用确认后再执行 `npm run build` 提升为正式版。

构建脚本刻意**不做压缩、转译、打包**，只做字符串替换；产物必须能 `file://` 打开且零网络依赖。两个构建期守卫值得知道：

1. **替换一律用函数形式** `str.replace(TOKEN, () => content)`。用字符串形式会让 `$&`、`$1` 被当成替换模式 —— 本项目 `app.js` 里就有 `.replace(/(\d\d)(\d\d)/, "$1:$2")`，会被静默吃掉
2. 构建后逐字节校验产物里能找到两份原文（`out.includes(css)` / `out.includes(js)`），并拦下内联内容里的 `</script>` / `</style>`（会提前闭合标签）

改动 `src/` 之后**必须重新构建**，否则 `index.html` 会停留在旧版本 —— 这也是 `npm run check` 存在的意义（可挂到 pre-commit 或 CI）。

## 部署到 GitHub Pages

`index.html` 在仓库根目录且已提交，因此 Pages 选择 **Branch: main / 目录: / (root)** 即可，无需任何构建步骤。

```bash
git init
git add .
git commit -m "feat: 股票收益计算器 v1.0"
git branch -M main
git remote add origin <你的仓库地址>
git push -u origin main
```

之后在仓库 Settings → Pages 里选 `main` / `/(root)`。
